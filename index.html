01 — Planteamiento

El problema de la búsqueda

La búsqueda consiste en determinar si un elemento existe dentro de una estructura de datos y, en caso afirmativo, localizar su posición. Es una operación fundamental en motores de búsqueda, sistemas de bases de datos, compiladores y estructuras en memoria.

El rendimiento de un algoritmo de búsqueda se expresa mediante su complejidad temporal: mejor caso, peor caso y caso promedio. La selección del método adecuado condiciona la eficiencia global del sistema.

Elementodato que se localiza dentro de la estructura
Clavevalor identificador del elemento buscado
Comparaciónoperación de igualdad entre dos claves
Complejidadcosto medible en tiempo y espacio

Todo algoritmo de búsqueda debe garantizar corrección (encuentra el elemento si existe) y completitud (termina en un tiempo finito).

02 — Búsqueda secuencial

Recorrido lineal

O(n)

La búsqueda secuencial examina los elementos en orden, uno por uno, hasta localizar el objetivo o agotar la estructura. No requiere que los datos estén previamente ordenados.

Su complejidad en el peor caso es O(n), equivalente al número de elementos de la colección; en el mejor caso, si el objetivo ocupa la primera posición, es O(1).

1mejor caso O(1)
npeor caso O(n)
0sin requisito de orden

Aplicable a listas cortas, implementaciones con centinela y como método auxiliar en algoritmos híbridos.

FIG. 01 · Recorrido secuencial● evaluando
n = 20 · iteraciones: 0objetivo: —
pseudocódigoalg. 01 · O(n)
secuencial(A[0..n−1], x):
  para i ← 0 .. n−1 hacer
    si A[i] = x: devolver i
  devolver −1          // no encontrado

03 — Búsqueda binaria

División sucesiva del espacio

O(log n)

La búsqueda binaria localiza el elemento central y determina en qué mitad se encuentra el objetivo, descartando la otra mitad en cada iteración. El espacio de búsqueda se reduce geométricamente.

Requiere datos ordenados. Con 10⁶ elementos bastan aproximadamente 20 comparaciones, ya que n se reduce a log₂ n.

~20para 10⁶ datos
n/2descartados
✔requiere orden

Fundamento de los índices de bases de datos y de las estructuras ordenadas en memoria.

pseudocódigoalg. 02 · O(log n)
binaria(A[0..n−1], x):
  izq ← 0, der ← n−1
  mientras izq ≤ der hacer
    med ← ⌊(izq + der) / 2⌋
    si A[med] = x: devolver med
    si x < A[med]: der ← med−1  sino: izq ← med+1
  devolver −1

04 — Funciones de hash

Acceso directo por clave

O(1) promedio

Una función de hash transforma la clave en un índice dentro de la tabla de dispersión. No existe recorrido: se calcula la posición y se accede directamente al casillero correspondiente.

Cuando dos claves producen el mismo índice se produce una colisión, resoltable mediante listas enlazadas o direccionamiento abierto. En el caso promedio, el acceso es de complejidad constante.

1acceso promedio
±colisiones en cadena
✔sin requisito de orden

Técnicas de resolución de colisiones: encadenamiento, direccionamiento lineal, cuadrático y doble dispersión.

insertar(T[0..m−1], k, v):
  i ← h(k) mod m
  si T[i] = ∅: T[i] ← (k, v)
  sino: enlazar (k, v)      // colisión

buscar(T, k): i ← h(k) mod m; devolver T[i]

06 — Aplicaciones

Implementaciones en sistemas reales

Índice de un libro

El índice remite a un rango ordenado de páginas; la localización final se resuelve mediante búsqueda binaria sobre ese rango.

binaria

Directorio telefónico

Cada entrada se indexa por su inicial: la clave determina directamente la posición de acceso dentro del directorio.

hash

Caché del navegador

Los recursos consultados se almacenan bajo su dirección; la recuperación corresponde a un acceso directo, no a un recorrido.

hash

Mapa de un videojuego

El mundo se representa como una matriz; la coordenada de celda se resuelve mediante acceso directo por hash espacial.

hash espacial

Otros ámbitos de aplicación: índices B-tree en bases de datos, tablas de símbolos en compiladores, autocompletado, sistemas de archivos y cachés de CPU.

07 — Conclusiones

Criterios de selección

O(n)

Búsqueda secuencial

Recomendada cuando la colección es pequeña, no está ordenada o se recorre una sola vez. Implementación directa, sin estructura auxiliar.

O(log n)

Búsqueda binaria

Requiere orden previo; idónea para consultas repetidas sobre colecciones grandes y estáticas. Costo marginal por consulta.

O(1)

Funciones de hash

Ideal cuando las claves son conocidas y se requiere acceso próximo a constante. Exige una función de dispersión bien distribuida.

En la práctica, los sistemas híbridos combinan métodos: hash para el acceso directo y búsqueda binaria dentro de los conjuntos de colisión ordenados.
